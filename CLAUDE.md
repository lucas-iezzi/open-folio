## Architecture

This is a single-file Express server (`server.js`) with EJS templates and a SQLite database (`data/portfolio.db` via `better-sqlite3`).

**Data layer:** SQLite accessed synchronously through `better-sqlite3`. `loadProjects()` / `saveProjects()` / `sortedProjects()` are the main helpers. Projects are sorted by an integer `sort_order` column. The DB is auto-migrated on startup (new columns added with `ALTER TABLE` guarded by `pragma table_info`).

**Project schema:**
```json
{
  "slug": "my-project",
  "title": "...",
  "subtitle": "...",
  "pageTitle": "...",
  "thumbnail": "/images/projects/my-project/uuid.jpg",
  "thumbnailAlt": "...",
  "order": 0,
  "sections": [
    { "id": "uuid", "heading": "...", "body": "...", "images": [{ "src": "...", "alt": "..." }] }
  ]
}
```

`title` is the short card label shown on the homepage grid. `pageTitle` is the H1 shown on the project page — leave empty to fall back to `title`. `subtitle` appears below the H1.

**Routing:**
- `GET /` and `GET /projects/:slug` — public portfolio pages
- `GET|POST /admin/login`, `GET /admin/logout` — authentication (no `requireAuth` guard)
- Everything under `/admin/dashboard` and `/admin/projects/*` — protected by `requireAuth`
- `POST /admin/upload/:slug` — image upload (multer, stored in `public/images/projects/<slug>/`)
- `POST /admin/image/delete` — deletes an image file from disk
- `/api/v1/*` — REST API protected by bearer token (see below)

**Security model:** CSRF tokens are stored in the session and checked on every mutating admin route. The token is passed to templates as `csrfToken` and sent from `admin.js` via the `X-CSRF-Token` header (for JSON requests) or `_csrf` body field (for form POSTs). Session is regenerated on login to prevent session fixation. Slugs and image paths are validated with `sanitizeSlug()` and `validateImagePath()` before any disk access to prevent path traversal.

**Frontend:** Two separate JS/CSS bundles — `public/js/main.js` + `public/css/style.css` for the public site, `public/js/admin.js` + `public/css/admin.css` for the admin panel. No framework, no bundler. The admin form is fully client-side driven: sections are managed in a JS `sections[]` array and serialized to `sectionsJson` (a JSON string) on save, sent as a single AJAX POST.

**Image uploads:** Images land in `public/images/projects/<slug>/` with a UUID filename. The upload endpoint (`POST /admin/upload/:slug`) validates slug and MIME type before multer writes to disk. The `validateImagePath()` helper enforces the path pattern `/images/projects/<slug>/<filename>.<ext>` on every save, preventing arbitrary paths from being stored.

**CSRF token in admin JS:** `admin.js` reads the CSRF token from `<meta name="csrf-token">` — but this meta tag is **not** in `views/admin/partials/head.ejs`. It is injected inline by the form views themselves. If adding new admin pages, include `<meta name="csrf-token" content="<%= csrfToken %>">` in the `<head>`.

**Environment variables** (generated by `npm run setup`):
- `SESSION_SECRET` — express-session secret
- `ADMIN_PASSWORD_HASH` — bcrypt hash of the admin password
- `API_KEY` — bearer token for the REST API
- `PORT` — defaults to 3000
- `NODE_ENV` — set to `production` to enable secure cookies and HSTS

## REST API

All endpoints live under `/api/v1/` and require `Authorization: Bearer <API_KEY>`. Responses are JSON. No CSRF token needed — bearer auth replaces it.

```bash
# Read the API key from .env
API_KEY=$(grep '^API_KEY=' .env | cut -d= -f2)
BASE=http://localhost:3000

# List all projects
curl "$BASE/api/v1/projects" -H "Authorization: Bearer $API_KEY"

# Get one project (full sections)
curl "$BASE/api/v1/projects/golf-ball-picker" -H "Authorization: Bearer $API_KEY"

# Create a project
curl -X POST "$BASE/api/v1/projects" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"slug":"new-project","title":"New Project","subtitle":"...","sections":[]}'

# Partial update — only supplied fields change
curl -X PATCH "$BASE/api/v1/projects/golf-ball-picker" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"subtitle":"Updated subtitle","sections":[{"heading":"Overview","body":"...","images":[]}]}'

# Delete
curl -X DELETE "$BASE/api/v1/projects/old-project" -H "Authorization: Bearer $API_KEY"
```

**Writable fields for POST/PATCH:** `title`, `subtitle`, `pageTitle`, `thumbnail` (must match `/images/projects/<slug>/...`), `thumbnailAlt`, `order` (integer), `sections` (array — replaces all sections atomically).

Image files themselves must be uploaded via the admin panel or `POST /admin/upload/:slug` (session auth required). The API manages text and metadata only.

## Deployment (Hetzner + Caddy + PM2)

**What is and isn't in git:**
- Code, templates, CSS, JS, scripts — tracked in git
- `data/portfolio.db`, `public/images/projects/`, `.env`, `node_modules/` — gitignored; synced separately

**First deploy to a fresh server:**

```bash
# 1. On the server: clone repo and install deps
git clone https://github.com/lucas-iezzi/website ~/portfolio
cd ~/portfolio && npm install

# 2. Generate .env (sets SESSION_SECRET, ADMIN_PASSWORD_HASH, API_KEY)
npm run setup

# 3. Sync DB and images from local machine
rsync -avz data/portfolio.db user@SERVER:~/portfolio/data/
rsync -avz public/images/ user@SERVER:~/portfolio/public/images/

# 4. Start with PM2
npm install -g pm2
pm2 start ecosystem.config.js --env production
pm2 save && pm2 startup

# 5. Set up Caddy as reverse proxy
sudo cp Caddyfile.example /etc/caddy/Caddyfile   # edit domain if needed
sudo systemctl reload caddy                        # Caddy handles HTTPS automatically
```

**Subsequent code deploys:**

```bash
# On the server — DB and images are untouched
git pull && pm2 restart portfolio
```

**Backups (run locally):**

```bash
scp user@SERVER:~/portfolio/data/portfolio.db ./backup-$(date +%Y%m%d).db
```

The admin panel's **Export JSON** button also gives a portable snapshot of all project text/metadata at any time.

## Scripts

- `setup.js` — interactive: generates `.env` with secrets. Run once on first install, or to reset the admin password.
- `sync.sh` — run from your **local machine** to push/pull the database and images between local and the production server. Not intended to run on the server itself.

## Design System

The public site is a pixel-accurate port of lucasiezzi.com (Webflow). All values below are sourced directly from the live Webflow CSS at `https://cdn.prod.website-files.com/6898bc40e612756082172bf9/css/lucas-iezzi.webflow.shared.e8aca24fe.css`. When adding new pages or components, match these exactly — do not invent new sizes or weights.

### Font

**Montserrat** (Google Fonts), loaded in `views/partials/head.ejs` (public) and `views/admin/partials/head.ejs` (admin). Weights in use: 300, 400, 500, 600, 700.

| Role | Value | Where used |
|------|-------|------------|
| Body text | `#1a1b1f` | All main text (`--color-text`) |

### Layout

**Horizontal margins:** `.container` uses `padding-inline: 7%` — matching Webflow's `.section { margin-left: 7%; margin-right: 7% }`. At 1536px this is ~107px per side. Never add a `max-width` constraint to `.container` on the public site.

**Mobile:** At `≤640px`, container padding drops to `15px`.

**Full-bleed images:** On the project page, the hero image (`.project-hero-image`) and section images (`.project-section-images`) live **outside** `.container` so they run edge-to-edge. Text blocks stay inside `.container`.

**Homepage card grid:** 4 columns, `1rem` gap, `3:2` aspect ratio images, title centered below each card.

### CSS custom properties

All design tokens use the `--d-*` prefix in `public/css/style.css`. Edit these to restyle the whole site consistently:

```
--d-name-size:       40px       site name
--d-name-weight:     500
--d-bio-size:        24px       tagline
--d-bio-lh:          1.333
--d-card-size:       19.2px     card labels
--d-hero-top:        20px       space above hero
--d-hero-bot:        40px       space below tagline
--d-proj-header-mb:  48px       space after project header
--d-section-gap:     48px       space between project sections
```

### Admin panel

Admin pages share the Montserrat font and `#1a1b1f` text color but keep their own compact UI in `public/css/admin.css`. The admin aesthetic is intentionally utilitarian — cards, inputs, and buttons are distinct from the public site's editorial look.
