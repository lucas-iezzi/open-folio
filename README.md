# Lucas Iezzi — Portfolio Site

A self-hosted portfolio site built with Node.js, Express, EJS, and SQLite. Deployed on a DigitalOcean Droplet behind Caddy and Cloudflare.

## Stack

| Layer | Technology |
|---|---|
| Server | Node.js + Express |
| Templates | EJS (server-side rendered) |
| Database | SQLite via `better-sqlite3` |
| Auth | Session-based (bcrypt password, CSRF tokens) |
| Process manager | PM2 |
| Reverse proxy | Caddy (auto HTTPS via Let's Encrypt) |
| CDN / DNS | Cloudflare |
| Host | DigitalOcean Droplet |

## What lives where

| Location | What it is |
|---|---|
| `server.js` | Everything — routes, middleware, DB access |
| `views/` | EJS templates (public site + admin panel) |
| `public/` | CSS, JS, images |
| `scripts/setup.js` | Generates `.env` with secrets — run once on install or to reset password |
| `scripts/sync.sh` | Local-only script to push/pull DB and images to/from server |
| `templates/project.json` | Project schema template for creating new projects via the API |
| `Caddyfile.example` | Caddy reverse proxy config — copy to `/etc/caddy/Caddyfile` on the server |
| `ecosystem.config.js` | PM2 process manager config |
| `data/portfolio.db` | SQLite database — **not in git, sync manually** |
| `public/images/projects/` | Uploaded project images — **not in git, sync manually** |
| `.env` | Secrets — **not in git, generated by `npm run setup`** |

## Common server tasks

All commands run inside the SSH session unless noted.

### Deploy a code change

```bash
cd ~/portfolio
git pull
pm2 restart portfolio
```

### Check if the app is running

```bash
pm2 list
```

### View live logs

```bash
pm2 logs portfolio --lines 50
```

### Restart the app

```bash
pm2 restart portfolio --update-env
```

### Reset the admin password

```bash
cd ~/portfolio
node scripts/setup.js
pm2 restart portfolio --update-env
```

> `setup.js` overwrites the entire `.env`, but always writes `NODE_ENV=production` automatically.

### Check server environment

```bash
cat ~/portfolio/.env
```

## Syncing the database and images

The database and images are **not in git** — they live only on the server and your local machine. Use the sync script to move them between the two.

The script lives at `scripts/sync.sh` in this repo. Run it from your **local machine** (not from inside the SSH session).

```bash
bash scripts/sync.sh
```

It will ask which direction:
- **Push (local → server):** overwrites the server DB with your local copy and syncs all images up
- **Pull (server → local):** pulls the server DB down to your local machine (images are not pulled — they're large and rarely change)

> Always pull before pushing if you've made changes through the admin panel on the live site, otherwise you'll overwrite them.

## Creating projects via the API

`templates/project.json` contains the full project schema. Use it as a reference when generating project content with an LLM, then POST it to the API:

```bash
# Read API key from .env
API_KEY=$(grep '^API_KEY=' .env | cut -d= -f2)

# Create a new project
curl -X POST "https://firsthatchstudio.com/api/v1/projects" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d @my-new-project.json

# Update an existing project (only supplied fields change)
curl -X PATCH "https://firsthatchstudio.com/api/v1/projects/my-project" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d @my-new-project.json
```

Images must be uploaded separately via the admin panel — the API manages text and metadata only.

## Caddy config

Caddy runs as a systemd service and handles HTTPS automatically.

```bash
# View config
cat /etc/caddy/Caddyfile

# Reload after editing
systemctl reload caddy

# Check status / errors
journalctl -u caddy --lines 50 --no-pager
```

## Environment variables

Generated by `npm run setup`. Stored in `.env` on the server (never committed to git).

| Variable | Purpose |
|---|---|
| `SESSION_SECRET` | Signs session cookies |
| `ADMIN_PASSWORD_HASH` | bcrypt hash of the admin password |
| `API_KEY` | Bearer token for the REST API |
| `PORT` | Defaults to 3000 |
| `NODE_ENV` | Must be `production` on the server |
